# Furnio store presentation

Use actual current native app captures, never the earlier HTML prototype in place of the app. Use synthetic property/account names, not customer addresses, emails or balances. No composited change may imply UI or functionality absent from the submitted binary.

## Consistent visual direction

Cream backgrounds, forest-green panels, terracotta details, actual Furnio wordmark. Large readable headings, one message per frame and spacious device framing. No promotional discount claims, ratings, purchase badges or unsupported speed promises.

## Screenshot sequence

1. **Your next listing, reimagined.** — current Home/services view.
2. **Set the style. Keep the space.** — actual virtual-staging image selectors.
3. **Precision, down to the detail.** — actual item-removal canvas with magnifier.
4. **See the difference.** — actual original/result comparison.
5. **A new light on every listing.** — all three real twilight choices.
6. **Your work, in one place.** — actual projects view with fictional data.

Capture iOS and Android separately: do not present iOS system controls as Android screenshots. Capture an iPad set if tablet support stays enabled. Screenshots still need capture, composition, render inspection and owner review; this document is not the finished artwork.

## Output specifications

- Apple iPhone 6.9-inch: 1320 × 2868 portrait PNG/JPEG; confirm accepted device-family sizes in App Store Connect before upload.
- Google Play feature graphic: 1024 × 500, opaque PNG/JPEG.
- Google Play icon: 512 × 512, using the existing app icon.
- Android phone screenshots: capture native portrait screens and follow Play Console's aspect-ratio and resolution rules.

Sources: https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/ and https://support.google.com/googleplay/android-developer/answer/9866151
